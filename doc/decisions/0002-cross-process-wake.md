# D-002：跨进程唤醒采用 VVAR 接收队列

## 背景

IPC 的阻塞队列需要唤醒其它进程的用户任务。用户任务位于各自进程的用户调度器，生产者不能直接操作目标进程的就绪队列。需要选择一种跨地址空间唤醒机制，并决定唤醒数据如何随唤醒传递。

## 决策

- 每个进程在 VVAR 中设置任务接收队列。
- 跨进程唤醒时，生产者把目标任务和唤醒数据放入目标进程的接收队列（不修改任务状态）。
- 目标进程的调度循环在安全点把接收队列中的任务设置`Ready`状态并搬入本进程就绪队列。
- 接收队列不影响进程优先级；只有进入就绪队列后才按就绪队列优先级参与调度。
- 唤醒数据通过接收队列传递，具体生命周期/所有权由后续设计确定。

## 替代方案

- **把整个就绪队列搬入 VVAR**：暴露面过大，有安全问题；否决。
- **内核中介**：每次跨进程唤醒都进入内核，开销大；否决。
- **用户态中断**：需要硬件支持，当前不可用；否决。

## 后果

- 生产者只访问目标进程的接收队列，不直接操作目标就绪队列。
- 目标进程必须运行调度循环才能搬运接收队列；没有在线任务时可能无法及时更新优先级。
- 唤醒高优先级任务不能直接抢占目标进程的低优先级任务。
- 接收队列和唤醒数据的所有权、生命周期、容量、安全边界需要后续设计。
- 相关未决项由 Q-041/Q-042 跟踪。
